Interactions

Keyboard & windows

Everything is reachable from the keyboard. One rule governs navigation and quitting: move forward with ↵, back out one level with q / Esc.

1At a glance

Without opening anything, the main screen shows every active session across every project at once, grouped by project, each showing its attention state R7. No keypress is needed to reveal a project.

Vocabulary note

The original requirement wording named four states — running, waiting, needs-reply, idle — written before the attention model was settled. Three states are final R6.7. “Waiting” and “needs-reply” are not a fourth state; “needs-reply” is what the question badge now covers.

3Navigation keys

R7.1 — main screen bindings.
KeyActionDetail
j k ←→↑↓ Move the selection Follows the tiles' current on-screen reading order — left to right, top to bottom, exactly as this frame's Mosaic placement put them. Moving past the last tile wraps to the first; past the first wraps to the last.
↵ Zoom Full-screen view of that session's trace: the chronological list of tool calls that fed its tile's one-line action summary — not just the latest line.
q Esc Back / quit Back out one level. From the main screen, exit and restore the terminal exactly as R2 describes.
? Help Overlay listing the current key bindings. ? again, or q / Esc, closes it and returns to whatever was showing underneath.
Reading order moves

Navigation follows the tiles' on-screen order for this frame — and that order is not guaranteed to stay the same from one frame to the next, because squarify gives no positional stability R5.7. Concretely: pressing j twice may not visit the same two tiles in the same sequence after the layout reflows. This is accepted, along with the motion itself.

4The footer

A footer bar is always visible on the main and trace screens — though not inside the ? overlay, which replaces it. It shows the current window value and the live/idle counts in this literal form R7.1:

window: 10m (3 live / 5 idle) j/k move · ↵ zoom · [ ] window · a all · w reset · ? help · q quit

Under “show all”, every session is active by definition, so the footer reads window: all (N live / 0 idle) instead of a minute count.

The footer is distinct from the empty-state panel that appears in the body when zero sessions are active — that panel is a different thing with different copy R9.

5Window controls

Six keys adjust W, the minutes-since-last-update cutoff that decides active vs. idle R8.

R8 — window keys.
KeyEffect
]W += 5m
[W -= 5m
Shift+]W += 1m — fine-tune
Shift+[W -= 1m — fine-tune
wReset W to the default, 10m
a“Show all” — every session counts as active regardless of age
Clamping

W is clamped to 1–60 minutes. [ never takes it below 1m; ] never takes it above 60m. Reaching “show all” happens only via a — pressing ] at 60m clamps and does not transition into “show all”.

Every window key triggers an immediate layout recompute: no animation, no debounce. The new layout appears on the very next drawn frame.

6Fixed defaults

These bindings are V1's fixed defaults. There is no in-app way to view or change what key triggers what — no settings screen, no config file read for this purpose R8.1. A future version may add rebinding; V1 reserves no visible UI for it.

Why

Picking these particular keys was a “good enough for now” choice, not a permanent commitment — the source's own framing is “use sensible defaults, we can switch them later.” The decision being recorded here is that not building rebinding is the deliberate part, not the specific letters.

7Still open here

The interaction questions that are not settled.
Open itemReq
Arrow-key semantics. The source lists “j/k or arrow” as one undifferentiated group and never says whether all four arrows should step one tile in reading order, or whether ↑/↓ should instead jump by on-screen row. The spec assumes all four are equivalent single-step until decided otherwise.R7.1
Project-level zoom. The source says ↵ zooms the selected “tile/project box”, but navigation only ever selects a tile — there is no described way to select a project box as a distinct unit. Only tile zoom is specified; what a project-level zoom would show is undefined.R7.1
Global overflow under a. With “show all” and 50+ sessions, tiles may still fall below the minimum size. Per-project degrade rules still apply, but there is no defined global +N strategy across projects at that scale.R8 / R5.6
Footer hint wording. The window: W (…) pattern is specified exactly; the wording of the key-hint reminder is left to implementation, as long as it accurately reflects the keys in this section.R7.1
